# Aura 横屏当前天气标题区设计

## 目标

重新排列 `320 x 240` 横屏首页顶部，让当前温度和天气状态占据原有地点、网络状态和天气源名称的空间。竖屏首页、天气数据源设置、天气请求流程和横屏预报图表不在本次调整范围内。

用户已选择 A「温度主导」方案。

本文档覆盖 `2026-08-22-landscape-weather-ui-design.md` 中“Landscape Home Layout”关于横屏标题区的描述；其余图表、主题、旋转和设置设计继续有效。

## 信息层级

横屏顶部按以下优先级展示：

1. 当前温度，使用 42px 字体，是顶部最醒目的信息。
2. 当前天气状态，使用 20px 字体并采用主题强调色。
3. 体感温度和湿度，使用 12px 字体与弱化色。
4. 最近更新时间，使用 12px 字体与弱化色。
5. 七天/逐小时切换和设置按钮保持现有视觉权重。

横屏首页不再显示地点名称、设备 IP 或天气源名称。`Shenzhen`、`Open-Meteo`、`QWeather` 等内容都不会出现在横屏首页，但相关信息和设置继续保留在竖屏或设置界面中。

## 布局

顶部区域维持现有 `0-58px` 高度，图表仍从 `y = 62` 开始。

- 当前温度位于左上角，建议边界为 `x = 6, y = 0, w = 76, h = 46`。
- 当前天气状态位于温度右侧，建议边界为 `x = 84, y = 5, w = 96, h = 24`。
- 体感温度和湿度位于天气状态下方，建议边界为 `x = 84, y = 32, w = 100, h = 16`。
- 更新时间位于左下方，建议边界为 `x = 6, y = 46, w = 74, h = 12`。
- 七天/逐小时按钮继续使用 `x = 188-282, y = 2-27`。
- 设置按钮继续使用 `x = 284, y = 2, w = 30, h = 25`。

天气状态应使用单行省略模式，确保较长翻译不会侵入右侧控制区。体感温度和湿度保持单行紧凑格式，例如 `体感 30° · 湿度 82%`。更新时间只显示时间，例如 `14:32 更新`，不带数据源名称。

## 视觉规则

- 当前温度使用主题正文色，度数符号使用主题高温色。
- 当前天气状态使用主题强调色。
- 体感、湿度和更新时间使用主题弱化色。
- 不增加顶部卡片、边框或背景块，保持现有沉浸式图表风格。
- 不增加当前天气大图标，避免与大温度争夺空间。
- 图表、七列日期、预报图标和预报天气描述的尺寸与位置保持不变。

## 数据与状态

天气快照仍提供当前温度、天气状态、体感温度、湿度和更新时间。渲染层只改变横屏标签的可见性、文本格式和位置，不改变数据获取或缓存逻辑。

横屏更新时间不依赖天气源名称。天气源切换、自动回退和重新获取天气后，只刷新显示时间及当前天气数据。

缺失数据时：

- 温度显示现有温度占位符。
- 天气状态显示 `--`。
- 体感温度或湿度缺失时，只显示可用字段；两者都缺失时隐藏该行。
- 更新时间缺失时显示 `--`，不重新显示天气源名称。

## 实现边界

本次实现只修改横屏标题区创建与状态刷新逻辑。竖屏首页继续显示其现有地点、网络状态和天气源信息。设置页中的地点与天气源控件不变。

应复用已内嵌的 42px、20px 和 12px 字体，避免新增字体资源。若非中文语言的天气状态超过可用宽度，使用省略号，不缩小字体或移动右侧按钮。

## 验证

自动化检查应覆盖：

- 横屏标题区不创建或不显示地点、网络状态和天气源名称。
- 横屏温度使用 42px 字体，天气状态使用 20px 字体。
- 横屏更新时间文本不包含 `Open-Meteo` 或 `QWeather`。
- 竖屏状态显示与天气源设置行为保持不变。
- 图表坐标、七列预报坐标、切换按钮和设置按钮保持现有值。

视觉检查应覆盖五套主题、中英文、长天气状态、温度占位符和无更新时间状态。在 `320 x 240` 画布内，温度、天气状态、体感/湿度、更新时间和右侧控制不得重叠。

## 验收标准

- 横屏首页不显示地点名称、设备 IP 或天气源名称。
- 当前温度清晰占据左上主要空间，字号为 42px。
- 当前天气状态字号为 20px，并与温度形成同一视觉组。
- 图表和底部预报区域不下移、不缩小。
- 七天/逐小时切换和设置按钮的位置与交互不变。
- 竖屏首页和设置页不受影响。
